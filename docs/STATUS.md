## P1 foundation: built

Shell, command palette and menus; editor with tree-sitter highlighting, marks, multi-cursor and VoiceOver; theme from the brand tokens and density modes; GitKit (clone over SSH or HTTPS, checkpoints, commit composer with secret scan, timeline, Sync, offline push queue, branches, conflicts with agent proposals, Undo); WorkspaceKit (recent projects, reopen at launch, live file watching); SecretsKit (Keychain, Secure Enclave SSH key, tokens, secret scanner); PolicyKit (approval tiers, tighten-only project rules, capability tokens, hash-chained audit log); Settings; plane mode; Acknowledgements.

Editor navigation: tabs (preview tabs, overflow past 8, ⌃Tab), quick open (⌘P), find in project (⇧⌘F), go to line (⌘L), go to symbol (⇧⌘O and `@` in the palette; `?` sends a task to the agent), and file operations in the navigator (new, rename, duplicate, delete after a checkpoint).

Cloning over HTTPS from Codeberg (Forgejo) and GitLab works on the iPad, HEADs matching: forgejo/docs (11 MB, 360 files) in 1.3 s, GitLab's plain-html in 1.8 s. That needed a libgit2 fix (scripts/patches): its SecureTransport stream asked for more than SecureTransport had decrypted, so the last of a pack waited for the server's next packet, 15 s on Codeberg. `OMNIE_LIVE_FORGES=1 swift test --filter LiveForgeTests` checks it from a Mac.

Open from the P1 bar: your hands-on editor checks; SSH to forges other than GitHub, and Origin, aren't tested.

## P2 plane-ready agent: mostly built

- **Models (ModelKit):** pinned, checksum-verified downloads (Tiny 0.5B, Standard 7B). Tiny drafts commit messages (0.19 s) and ghost text (~0.45 s after you stop typing).
- **Agent (AgentKit):** typed tools, policy on every call, journal and resume, a task branch and worktree per task, changeset review hunk by hunk, squash merge with an `Assisted-by` trailer. Agent pane on iPad, Agent and Changes tabs on iPhone. **Test guard:** when the goal is to make tests pass (and doesn't ask for test changes), edits to test files are refused with a pointer to the code under test. On the iPad the local 7B had rewritten `orbit.test.ts` five times and run out of steps; with the guard it fixed `src/orbit.ts` and the tests passed, in 136 s, offline.
- **Online models (start of P4):** Anthropic or any OpenAI-compatible API for agent tasks (Settings › Models), keys in the Keychain, consent per project with Face ID, routing Local / Online / Auto with plane mode forcing local. On the golden set, Claude Sonnet 5.5 passes **25/25** (~35 s a task) where the local 7B passes 18/25.
- **Quality:** golden task set, 25 tasks, run on the device with `-OmnieAgentEval`: **18/25 (72%)**, about 40 s a task, plateaued for the 4-bit 7B; what's left is the model's judgment. See `spikes/agent-p2.md`.
- **Edit guard:** besides JSON, edits that would leave JavaScript/TypeScript unparseable are refused with the line (RunKit's transpiler parses them); a file that was already broken can still be edited.
- **Security:** red-team corpus v1 (7 attack cases, real PolicyKit, approvals denied); it found and closed a symlink escape.

Open: an agreed pass rate on a larger task set (the router can already send what the local 7B can't do to an online model).

## P3 sandbox and tools: exit test passes

**The plane test passes on the iPad** (PLAN's P3 bar): a Vite-style three.js project is cloned and prepared online, then in plane mode the local 7B fixes it, its tests and type check pass, the preview and the Stage run, a commit is made and the push queues; with plane mode off, the push lands. 67–70 s end to end, unattended (`scripts/plane-test.sh`). See `spikes/plane-test-p3.md`.


- **RunKit:** JavaScript/TypeScript (Sucrase in JavaScriptCore, ES modules in WKWebView) and Python (Pyodide) run on the device with no network and a timeout; vitest- and pytest-compatible subsets run a project's own tests. The agent has `run_tests` and `run_script`.
- **WASI (wasm32-wasip1) programs:** RunKit's own preview1 layer passes **73 of 73** of wasi-testsuite on the iPad (6.1 s for the suite; the P0 spike's shim passed 55). Programs run in a worker in the sandboxed web view against the project: files load on first read, and what a program writes, moves or deletes is applied inside the project when it exits. Paths can't leave the directory they're resolved from, rights only shrink, no sockets, a memory cap, a timeout, and **fuel**: each module is instrumented at load so every call and loop iteration spends from a budget (20 billion units by default, about 10% slower), which stops runaways deterministically; the suite still passes 73/73 with it, on the iPad too. In the terminal: `time <command>` (wall clock, plus fuel used and peak memory for WASI runs); bundled `jq` (jq's language through jaq) and `rg` (ripgrep's searcher, printer and .gitignore-aware walker, single-threaded, with its common flags; results are links); pipes between any of them and the built-ins (`cat package.json | jq -r '.dependencies | keys[]' | sort`, `rg -o '[a-z]+' | sort | uniq -c | sort -rn | head`, with `wc`, `sort`, `uniq`, and `cat`, `head`, `tail`, `grep` reading the pipe) and `> file` / `>> file` into the project (the open file is saved first and reloaded after), `./tool.wasm`, and project tools in `tools/` or `.omnie/tools/` by name; the agent's `run_script` runs `.wasm` too. On the iPad, a jq query takes 166 ms; `rg -c` over a 237-file tree takes 345–447 ms, most of it starting the sandbox (3 million fuel, 1.8 MB), against 139 ms for the built-in Swift `grep`; pipes run there too.
- **Conflict resolver, agent proposals:** "Propose" asks the model (the agent's router: local in plane mode, consent before code goes online) to merge each conflict block from both sides and the lines around it; the result is marked "Proposed by …" for review, and a merge that used proposals carries an `Assisted-by` trailer. On the iPad the local 7B merged a two-file conflict correctly (1.4 s and 2.2 s per file: "Shows between 1 and 25 items", the raised limit kept beside the new constant). Repeated context in a small model's reply is trimmed.
- **Workspace spec (PLAN §8.2), device half:** tasks come from `.devcontainer/devcontainer.json` (`run.tasks`, comments allowed) or `package.json` scripts. `npm run <script>`, `npm test`, `yarn <script>`, `task <name>` and the palette's "Run task: dev/test/build" run them through the built-in shell, part by part for `a && b`, saying they ran on this iPad; `vite` opens the preview and `tsc` runs the type check. A task that needs a real toolchain (`docker`, `cargo`, `vite build`…) says it belongs on a remote host (P4). The spec's `image`, `forwardPorts`, `network.allow` and `deploy` are read for the remote half; the allowlist isn't given to the agent's policy (a cloned repo could otherwise grant itself network access).
- **Sketch and screenshot → code (§11.2):** Tools › Sketch opens a full-screen PencilKit whiteboard (or picks an image); an online vision model writes the UI in the project's stack (React/TS, Vue, Svelte, SwiftUI or plain HTML, read from the project, with a short existing component for style) as a task branch and changeset to review. New components go where the project keeps them (moved there with their imports if the model puts them elsewhere); configuration is never touched and JS/TS must parse. Offline or in plane mode the drawing waits in a queue and goes on reconnect. On the iPad: a drawn sign-in wireframe became `src/components/SignInCard.tsx` plus the App change in 5–11 s with Sonnet 5.5.
- **Choosing what to commit (§9.10):** the commit composer's "Chosen changes" shows each file's not-staged and staged hunks: swipe a hunk right to stage it (left to unstage), tap lines and press S, or stage a whole file; Commit then commits only the index. "Everything" stays the default. Staging works on text (the index's version, the file and the chosen lines give the new index version) and checkpoints leave the index alone. Tests cover partial lines, end-of-file newlines, new and deleted files, unstaging and committing; a UI test stages one line and commits it; on the iPad the same takes 24 ms.
- **Git LFS:** a libgit2 filter does what git-lfs's does: files marked `filter=lfs` are stored in `.git/lfs/objects` and committed as pointers, and checked out with their content, so status and diffs see the real files. The batch API (HTTPS, the same token as git; SSH remotes map to their host's HTTPS) downloads after clone and Sync, uploads before pushes and queued pushes, and a move to another forge carries the objects. Git › Download Git LFS files fetches what's missing. Tested with a local LFS server (filter, push, pull, bad credentials), against gitea.com (30 files, checksums match), and on the iPad: cloning that repo brings its 30 LFS files with their content in 9.4 s.
- **Remotes and moving a repo (§9.10, §9.11):** Git › Remotes… lists remotes by host ("origin · forgejo.example.net"), and adds, renames, re-points or removes them. **Move this repo** previews then runs: add the new forge, push your branches and tags (agent task branches stay local), make branches track it, keep the old remote fetch-only (its push URL is unusable on purpose; "Allow pushes again" undoes it). Approved like a push, refused offline, safe to re-run. Tested against local bare repositories, in a UI test (preview), and on the iPad (16 ms). Cloning an empty repository now starts on `main`, not libgit2's `master` (iOS has no global gitconfig to say otherwise).
- **Blame (§9.10):** Git › Toggle blame (⌥⌘B) puts a column beside the code: each run of lines with its author and age, a violet bar for lines from agent commits (their `Assisted-by` trailer), ion for lines you haven't committed (it blames the editor's text, not the saved file); tap a run to open its commit in the timeline. VoiceOver reads each run. On the iPad, the plane test's `orbit.ts` blames in 11 ms with the agent's fix marked.
- **Timeline operations (§9.10):** each commit's menu has Tag… (annotated with a message, lightweight without; tags show on the rows, and delete from the same menu), Revert, and Reset to here (keep changes): the later commits leave the branch, what they changed stays uncommitted, Undo puts them back, pushed commits are refused. "Show everything" lists the reflog. UI test: tag, reset, undo, reflog; the same steps pass on the iPad.
- **Edit history (interactive rebase, §9.10):** Git › Edit history… (and the timeline) lists your unpushed commits, oldest first: drag to reorder, and keep, reword, squash, fix up or drop each. The result is previewed as you go (a dry run that changes nothing; a commit that wouldn't apply in its new place is named), applied after a checkpoint, and one Undo puts the old history back. Untracked files are left alone; original authors and dates are kept. UI test: drop, drag-reorder, fix up, apply, timeline, undo. On the iPad the rewrite takes 15 ms.
- **Split editor:** "Open in split" (⌘\\) opens the file in Editor 2, a second editor that is a panel like the others: beside the main one by default, or below, or in its own window. It has its own file (pick from tabs or recent files) and autosaves 3 s after typing; with the same file in both, a save in either shows up in the other unless it has unsaved edits. UI test: typed in Editor 2, saved, seen in the main editor. On the iPad it opens as its own group in the right dock.
- **Breadcrumbs and sticky scroll:** above the code, folder › file › the symbols around the caret (tap one to select it; the unsaved dot moved here); while scrolling, the headers of the classes and functions the top line is inside stay pinned (up to three; tap to go there). Scopes come from the outline symbols and indentation (LangKit `Outline.scopes`), recomputed off the main thread 300 ms after edits. On the iPad, AgentModel.swift (22 scopes) shows `AgentModel › finish` at the caret and pins `AgentModel › run` at line 196.
- **Bracket matching:** the bracket at the caret and its partner are highlighted, nesting counted and brackets inside one-line string literals skipped, within 20,000 characters either side (2.6–3.3 ms on the iPad in a 1.2 M-character file).
- **Minimap:** beside the editor, a row per line (indent and length), error/warning/diff/agent ticks and the visible band; tap or drag to scroll, VoiceOver pages with it, "Toggle minimap" in View. A 20,000-line file maps in 12–19 ms on the iPad.
- **Welcome (first run):** three ways to start (try the sample project, open a folder, clone) and optional setup (commit author, local model, online model), in the plan's voice; shown once, Help › Welcome brings it back. The sample is the plane test's project, installed as a committed repo with its README open: run the tests (two fail), ask the agent, see it in Stage. On the iPad the sample installs and `npm test` shows the two failures in 165 ms. UI test: welcome → sample → README in the editor. Layouts are now kept per project (§13), falling back to the last one.
- **Panes you arrange:** the editor sits between three docks (left, right, bottom). Every panel (Files, Agent, Timeline, Terminal, Preview, Stage, Tools) is a tab that drags to any group or dock edge, or moves from its menu (Move to a dock, beside another group, Close); docks and groups resize by their boundaries (double-tap resets, VoiceOver adjusts), ⌘1/⌘3/⌘J toggle the docks, and four presets start you off. Any panel also opens in a window of its own (a second iPad window or an external display); closing the window puts it back in a dock. The layout is kept between launches. Side docks show when they fit beside a 480 pt editor, else the one used last. UI tests cover moving by menu, dragging, and the relaunch.
- **Profiler (§11.2):** every terminal command this session is timed (and WASI runs' fuel and memory); the Runs tool compares each command's latest run with the one before (+/−%) with a bar of the last ten; the preview's DevTools has a Perf tab for the page's `performance.measure`s; the Stage HUD has frame times.
- **Colors (§11.2 color + design-token picker):** a WCAG contrast checker; the project's `tokens.json` as swatches by theme, editable in place (only the value changes in the file), with text/surface pairs below AA listed; dominant colors of a project image. It flags our own brand file: dark `text.tertiary` on `surface.raised` is 4.34:1, under AA (yours to decide; it's used for tertiary labels).
- **Binary viewer (§11.2 WASM inspector + hex):** files the editor can't show (binary, or over 8 MB) open in a byte view; a `.wasm` file also shows its sections with sizes, imports, exports, functions, memory and data segments.
- **Log viewer (in the terminal):** a text filter and an errors-only toggle; any line naming a project file and line (TypeScript errors, stack frames, Python tracebacks, uncaught errors, which now say where they were thrown) opens the file there; JSON lines expand to formatted JSON.
- **Terminal tab (TermKit):** built-in commands over the project (ls, cd, cat, grep, run, test, git status/log/diff, open), Run tests and Run file.
- **Preview:** a project's index.html live, TypeScript transpiled on the fly, reload on save. **DevTools-lite** below it: the console; every request the page made (from RunKit's scheme handler: status, kind, size, time, mocks marked; requests to the internet listed as blocked); and the DOM as an outline where tapping a node outlines it in the page and shows its size, box, font, colours and attributes.
- **Offline package cache, first tier:** three.js bundled and import-mapped, so `import * as THREE from "three"` works offline in previews, runs and tests.
- **Offline package cache, npm tier:** `npm install [name[@range]]` in the terminal (or Prepare for offline, per project) fetches packages and their dependencies from the registry, checks each against its integrity hash and unpacks it into Application Support. Previews, runs and tests then import them from the project's package.json with no connection: ES modules as they are, CommonJS wrapped as ES modules with named exports found statically. Checked with React 18 (server render), zod, date-fns, nanoid and lodash-es. On the iPad: `npm install zod` 0.39 s, a run that imports it 54 ms, a type check against its declarations 258 ms.
- **Offline package cache, Python tier:** `pip install [name…]` or `pip install -r requirements.txt` (or Prepare for offline) fetches Pyodide's own builds (numpy, pandas and the rest of its 357 packages, pinned by its lock file) from its CDN and pure-Python wheels from PyPI, each checked by sha256, with dependencies resolved (PEP 440 versions, PEP 508 markers evaluated for Pyodide). Scripts and tests load them from requirements.txt or pyproject.toml with no connection. On the iPad: `pip install numpy tabulate` 0.4 s, a script using both 1.2–1.4 s.
- **Stage:** glTF/GLB, OBJ and STL from the project in three.js, with a native performance HUD. Scene modules (`*.stage.js`/`.ts`, `export default ({ THREE, scene, onFrame }) => …`) run there too; shaders (`.glsl`, `.vert`, `.frag`, `?raw`) import as strings. Saving reloads the stage with the camera where it was, and shader compile errors land on the shader's line in the editor and in Problems. A scene inspector lists the objects (tap one in the viewport to select it) and edits transforms, visibility, material colours, roughness, metalness, opacity and shader uniforms live, until the next reload. **"Write to code (N)"** hands the inspector's edits to the agent as a precise task on the scene module, so they land as a reviewable changeset: on the iPad, Sonnet 5.5 made exactly the change (color where the cube is created, its position after); the local 7B's tries were caught by the new syntax guard and then misplaced, so review it. The agent's read-only `stage_scene` tool sees the same scene graph (as loaded or last edited) and the HUD numbers. On the iPad: 60 fps (WKWebView caps animation frames at 60 Hz). Python starts and runs in under a second. See `spikes/runkit-p3.md`. **View in AR:** the scene exports as USDZ (three.js's exporter, without the grid and selection box) and opens in AR Quick Look at real size, with Share to save it; on the iPad the planets scene exports in 21 ms (90 KB) and ModelIO reads both meshes back.
- **Tools tab (ToolsKit):** the snippet vault (SQLite with full-text search; "Save selection as snippet", insert at the caret; pinned snippets go to the agent with every task, and it has `snippets_search`), the diff tool (any two project files or pasted text, git's diff engine and the review's colors; "Compare open file with…" in the palette), HTTP client (`.http` files, secrets from the Keychain), API mock server (recorded responses, and routes generated from an OpenAPI or Swagger spec, JSON or YAML, in the project, served to previews), SQLite browser (read-only by default; the agent gets a read-only `sqlite_query` in projects with a database) and the Patterns lab (JSON with jq queries through the bundled WASI jq; YAML shown as JSON and JSON turned into YAML; regex in JS and Swift flavors with a piece-by-piece explainer; a cron explainer with the next runs, deterministic as PLAN asks).
- **Offline docs:** DevDocs bundles (MDN JavaScript, DOM, CSS, Python, Node, three.js, React, NumPy, pandas, git, and the rest of its 837) downloaded from Help › Search docs (⇧⌘D, which starts with the word at the caret), then searched and read with no connection; links between pages work, scripts don't run. The agent has `docs_lookup` when any are installed. DevDocs publishes no checksums, so the download's sha256 is recorded instead.
- **Markdown + Mermaid preview** in the Preview tab for the open `.md` file; it follows the caret (each block knows its source line) and exports to a paginated A4 PDF beside the file.
- **Type checking:** TypeScript 5.9 runs offline over the whole project (tsconfig.json honoured; without one, Vite-like defaults with every file a module; with the declarations of packages in the offline cache) when it opens and after saves: underlines in the editor, an error count in the status strip, a Problems list (⇧⌘M). The agent has `check_types` in TypeScript projects.

Open: more bundled WASI tools (a shell's coreutils next), PyPI packages with compiled code that Pyodide doesn't build, a better local model for small structural edits.

## How to check things yourself

- Debug launch arguments (debug builds): `-OmniePlaneTest <bare repo in Documents>`, `-OmnieWasiConformance`, `-OmnieOpenFolder <path in Documents>`, `-OmnieRunTests`, `-OmniePreview`, `-OmnieAgentDemo`, `-OmnieAgentTask "<goal>"`, `-OmnieAgentEval <label>`, `-OmnieModelSmoke`.
- Packages: `swift test` in each `packages/*` (EditorKit runs on the simulator: `xcodebuild test -scheme EditorKit`).
- CI (`.github/workflows/ci.yml`): REUSE lint on Linux; every package's tests on `macos-26` for each push and pull request; the UI tests on main, nightly and by hand. Standard GitHub-hosted runners are free for this public repository; the vendored inputs are cached on their scripts' hashes.
- `scripts/test-all.sh [--ui]` runs every package's tests (EditorKit on an iPad simulator) and, with `--ui`, the app's UI tests; one line per suite, non-zero exit on any failure. 13 suites, 274 tests, about 1.5 minutes.
- Vendored inputs (gitignored): `scripts/build-git-deps.sh`, `scripts/vendor-grammars.py`, `scripts/vendor-runkit.sh`, `scripts/vendor-wasi-spike.py`.
